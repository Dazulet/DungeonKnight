# Decisions

## Week 10: Assignment 10, three enemy types

- **2026-11-10.** I asked Claude Code to check that the Shooter can hit a moving player. It fired only 3 times in 40 seconds and never hit. Its "too close" distance (3.5 m) was too big for my small arena, and it aimed at where I was, not where I was going. We changed the distance to 2.5 m and added aim lead. The aim line still locks 0.25 s before the shot, so a side step can dodge it.
- **2026-11-10.** I asked Claude Code to audit all three enemies for fair combat. The Patroller's hit only checked distance, so it could hit me through the edge of a pillar. Also, no enemy checked if I was on the screen. We added a line-of-sight check before the hit and an on-screen check before every attack.
- **2026-11-10.** In a test, some enemies died without ever seeing me, because I could shoot them from farther than they can see. I asked Claude Code to make enemies react to hits, but without seeing through walls. Now a hit turns the enemy toward the shot, and for 3 seconds it can see farther. Walls still block its sight.
- **2026-11-10.** I found out that all this work was committed in the wrong local project folder (github.com/Nurzhigit08/DungeonKnight), not in my repository. I asked Claude Code to audit both projects first. All asset GUIDs were the same, so we moved the work file by file in 6 stages, without copying any Git history. After each stage we ran the Unity tests again in my project before I made the commit.
- **2026-11-11.** Playtest: two testers, my two younger brothers (two different people), played the game for the first time. Tester 1 won on the first try. Tester 2 won on the first try. Both said the game was too easy, and the target is 2–4 tries. In our tests the enemies often died before they could finish an attack. I asked Claude Code for fair changes. We changed Patroller health 4 → 6, Charger health 5 → 7 and Shooter cooldown 1.8 s → 1.4 s. The wind-ups, warnings and damage did not change. New players have not tested these changes yet.

## Week 11: Assignment 11, data and saves

- **2026-11-17.** I asked Claude Code to move every balance number into ScriptableObjects. It made 9 data assets (Patroller, Shooter, Charger, Slime, Bat, Knight, Coin, Endless waves) and moved 114 values out of the prefabs. A script compared every old prefab value with the new asset value: all equal. All 156 Assignment 10 test checks still pass, so the balance did not change. Colours, screen shake, warning visuals and the steering/stuck checks stay in the components, because they change the feel, not the difficulty.
- **2026-11-17.** Two problems found while testing data changes: the HUD had exactly 3 heart images, so `Max Hearts 5` in KnightStats changed the game but not the screen. The HUD now adds hearts to match the data. And an enemy reported its death before it added its points, so the best score saved after the last kill was missing that enemy. We swapped the order.
- **2026-11-17.** Three levels are three LevelData assets loaded by the same Dungeon scene. Level 1 is exactly the Assignment 10 fight (5 enemies) with a 2:00 limit, so playtest 1 and the old tests stay valid. Level 2: 7 enemies, 2:30. Level 3: the same 7 plus 2 reinforcements after 25 s, 3:00. The agent first put a Charger facing straight into a pillar; we moved it to (8, 4) facing down. A test now checks that no spawn point is inside a wall and no enemy sees the player at the start.
- **2026-11-17.** Save system: JsonUtility writes `save.json` in persistentDataPath (no BinaryFormatter). The agent's first version gave the `version` field a default of 1, so a file without a version was accepted as valid. Now the default is 0 and such a file is rejected. A broken file is copied to `save.broken.json` and the game starts with defaults. It saves after a win, on every settings change and in `OnApplicationPause(true)`.
- **2026-11-17.** The game has no sound yet, so a music volume slider would do nothing. The two settings are real: screen shake on/off and auto aim on/off. Reset Progress asks for confirmation and keeps the settings. Everything was tested in the Unity Editor with automated tests; the phone restart test and the broken-file test on the phone are still to do.
